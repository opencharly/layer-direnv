# 2026.242.1147 — fix(direnv): correct the shell drop-in paths to match the schema output

## Summary
The check-charly-fedora-pod / check-fedora-test-pod check-image steps failed on the direnv shell drop-in checks: the layer-direnv candy's checks expected `/etc/profile.d/charly-layer-direnv-bash.sh` and `/etc/fish/conf.d/charly-layer-direnv.fish`, but the shell: schema (spec/install_step_vocab.go, OCITarget rendering) actually emits `/etc/profile.d/charly-direnv-<shell>.sh` and `/etc/fish/conf.d/charly-direnv.fish` — the candy name is `direnv`, not `layer-direnv`. The drop-ins WERE baked into the image (verified in the build log: `charly-direnv-bash.sh`, `charly-direnv.fish`), but the checks looked at the wrong paths, so they failed with exists=false.

Fix: correct the layer-direnv candy's description and check file paths to `charly-direnv-*` (matching the schema's actual output).
